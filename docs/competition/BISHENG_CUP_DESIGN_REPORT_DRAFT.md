# 毕昇杯初赛设计报告初稿

> 本文件是内容底稿，不是赛区统一格式的最终提交文件。最终应复制到赛区要求的模板，并由队伍核对题目、队员、指导教师、日期和图片。

## 摘要

针对校园便利点、宿舍无人货柜和办公室零食柜中人工收银成本高、无人值守时误计费难追溯的问题，设计一套运行在 QSM368ZP-WF/RK3568 类嵌入式 Linux 平台上的自助收银终端。系统以 USB HID 条码输入完成可靠计费，在板端通过 Qt/QML 提供 HDMI 收银界面，Flask/SQLite 管理商品、购物车和订单；扫码后触发摄像头采集，并由 RKNN/NPU 视觉模型给出商品 Top-3 结果，用于一致性校验和未知条码候选。视觉结果不直接连续加入购物车，只有用户明确确认时才允许候选操作，从机制上降低误识别和重复收费风险。系统同时提供中文语音命令、固定提示音和演示支付状态回写，形成“扫码—计价—校验—反馈—支付—订单”的端侧闭环。

## 1. 需求与场景

### 1.1 场景

- 小型校园便利点和办公室零食柜；
- 无专职收银员的自助结算台；
- 网络不稳定但仍需要本地购物车和订单状态的环境。

### 1.2 设计目标

1. 计费链路简单、可解释、可恢复；
2. 端侧完成主要交互，避免电脑浏览器成为系统必需品；
3. 视觉识别用于校验而不是替代可靠条码计费；
4. 给扫码、拍照、语音、支付异常提供明确的屏幕和声音反馈；
5. 采用可获得的嵌入式板和 USB 外设，控制成本。

## 2. 系统方案

```text
扫码枪/HID ─┐
摄像头 ─────┼─> 板端 Flask + SQLite ─> Qt/QML HDMI 收银台
麦克风 ─────┘          │                  │
                       ├─> RKNN/NPU Top-3  ├─> 中文播报
                       ├─> 本地订单/二维码  └─> 支付状态
                       └─> 仿真云支付服务（可选，网络失败可降级）
```

### 2.1 主流程

```text
条码输入
  -> 查商品与价格
  -> 加入购物车、刷新总价
  -> 拍照并运行视觉校验
  -> 显示 Top-3/置信度/延迟，不自动重复加购
  -> 用户结账
  -> 生成本地订单和支付二维码
  -> 云端可用时演示 paid 回写，否则显示本地/局域网状态
```

### 2.2 故障策略

- Qt/Weston：提供 `start_retail_hdmi_qml.sh` 和 `restore_default_weston.sh`；
- 视觉：RKNN CLI/NPU 为主，ONNX Runtime 为兼容 fallback；
- 网络：云支付不可达时不影响本地购物车和订单创建，并明确显示降级状态；
- 摄像头：互斥、冷却、超时和旧照片清理，避免连续点击假死；
- 输入：扫码枪 HID 作为主输入，未知条码显示原文和原因，不静默丢弃。

## 3. 核心创新点

1. **双通道职责分离**：条码解决“计费确定性”，视觉解决“商品一致性和未知候选”，两者不互相替代。
2. **端侧闭环**：本机 HDMI/QML、SQLite、RKNN/NPU、音频和 USB 输入组成完整终端形态。
3. **失败可解释**：未知条码、视觉低置信度、云支付不可达和音频设备缺失都转为用户可见状态。
4. **可回滚演示**：应用层启动/恢复脚本不改 boot/rootfs，便于现场排障。

## 5. 测试与结果边界

视觉 baseline 使用 117 张图片，固定测试集 18 张：Top-1 94.44%、Top-3 100%。此结果只说明当前数据划分上的流程有效；样本量小，不能替代不同光照、遮挡、角度和背景下的泛化验证。初赛报告应同时附失败样例和延迟，不只展示最好的一张预测图。

自动测试通过也不等价于现场通过。HDMI 可见性、扫码枪端口、摄像头、音频、网络和手机访问必须补本次现场照片/视频。

## 6. 成本与可实施性

成本表应由队伍根据实物采购价补齐，至少列出：嵌入式板、显示器、扫码枪、摄像头、USB 音频设备、存储/线材和可选网络设备。软件侧采用 Linux、Flask、SQLite、Qt/QML、ONNX/RKNN 工具链，避免把云服务器和真实商户支付费率写成硬件成本。
